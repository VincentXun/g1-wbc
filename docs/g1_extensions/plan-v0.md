# 人形机器人运控项目计划 V0

> 面向后续 AI /
> 开发者的需求与目标说明，不是固定实施方案。版本：V0；日期：2026-11-04。

## 1. 背景与目标

本人已有具身智能研究经历，希望在未来约 3
个月内，将能力重点拓展到**人形机器人运动控制**，服务于中国具身智能企业的人形运控岗位求职。项目尽量全部在仿真中完成；目前没有稳定的人形真机资源，算力上限为**单张
NVIDIA RTX 4090**。

项目目标： 1. 理解并复现人形机器人基础下肢 RL
Locomotion，如速度跟踪、身体高度控制。 2.
重点研究上肢操作过程中的腰部协调、身体姿态变化和全身稳定性。 3.
掌握并实践
FK、IK、Jacobian、任务空间控制，以及接触/负载条件下的稳定性评估。 4.
形成一个有实际操作意义、可量化评估的仿真 Demo。 5.
整理为可复现、可解释的简历项目，能清楚说明个人完成的算法和工程工作。

## 3. 项目重点与技术路线

### 3.1 下肢：成熟策略为基础，补足 RL Locomotion

下肢双足运动是人形运控的重要基础，但本项目不以从零训练复杂通用运动模型为目标。 -
复现 G1 下肢预训练策略和基础运动任务。 -
理解速度跟踪、身体高度控制、观测/动作空间、奖励设计和训练流程。 - 在单张
4090 可承受范围内，尝试独立训练基础 PPO Locomotion 策略。 -
比较预训练与自训练策略；自训练若受时间或算力限制，可作为补充，不阻塞主项目。

### 3.2 重点：上肢操作、腰部协调与全身稳定性

主要研究上肢操作如何影响整个人形机器人的姿态和稳定性，以及如何协调上肢、腰部与下肢。 -
上肢关节空间与任务空间控制。 - FK、IK、Jacobian 等运动学基础。 -
腰部与手臂的冗余协调，以及身体高度对末端可达性和操作姿态的影响。 -
上肢运动、物体负载和接触反作用对躯干姿态及整体稳定性的影响。 -
在完成末端任务的同时，约束或改善身体姿态、关节运动和接触行为。 -
根据实际可行性，探索接触反馈、基础阻抗/导纳控制或其他柔顺控制方法。

**重要边界：** AGILE 已有 PickPlace
不能描述成完整通用移动操作系统。现有配置主要围绕右臂/手部和腰部的参考轨迹跟踪，并调用冻结的下肢策略。连续移动接近、通用末端目标、完整移动---操作---撤离流程，以及系统性的稳定性实验，属于拟扩展内容，需要实施时进一步核对和开发。

### 3.3 Demo 方向：跨高度工位的移动操作

期望逐步形成： 1. G1 接近操作工位； 2. 根据工位高度调整身体高度或姿态；
3. 使用上肢完成简单物体抓取、搬放或受限接触操作； 4.
在不同操作高度、物体质量或接触条件下评估身体姿态和任务表现； 5.
条件允许时，扩展为不同工位之间的连续移动与操作。

不要求一开始实现全部流程。应从 AGILE
已有任务出发逐步扩展，优先保证物理交互真实、控制链条清晰、实验结果可量化。暂不要求复杂视觉感知、VLA、双臂高难度协同或真机部署。

## 5. 评估指标与实验要求

不能只以视频演示作为完成标准。应根据任务选择可记录、可比较的指标： -
任务成功率、完成时间或阶段成功率。 - 末端位置/姿态误差、轨迹跟踪误差。 -
躯干倾角、角速度或姿态偏差。 - 质心/基座运动变化（需说明指标定义）。 -
关节限位违反情况、动作平滑性或动作变化量。 -
物体负载、操作高度、接触条件变化下的性能退化。 -
外部扰动后的姿态恢复和任务恢复情况。 -
训练奖励、收敛表现、采样效率和显存占用。

应设置有意义的基线，例如固定腰部与允许腰部协调、不同稳定性约束、不同负载/高度条件等。具体指标、基线和实验数量由后续实施者结合代码能力确定。

## 7. 三个月阶段目标

### 阶段一：平台验证与官方任务复现（约第 1--2 周）

-   验证 AGILE 环境和 G1 模型能否在目标算力环境运行。
-   运行官方下肢预训练策略和基础任务。
-   运行 PickPlace，检查训练入口、参考轨迹、观测/动作配置和资源占用。
-   完成至少一次训练更新或小规模训练测试，避免只验证推理。

验收：可复现环境、任务运行记录、显存/吞吐记录和可用任务清单。

### 阶段二：基础能力复现（约第 3--4 周）

-   复现下肢速度/高度控制。
-   运行上肢 PickPlace 轨迹跟踪训练。
-   形成基线视频、训练曲线和基本定量评估。

验收：能解释上下肢策略分别控制什么、输入输出是什么、哪些部分被冻结。

### 阶段三：上肢任务空间与腰部协调（约第 5--7 周）

-   建立或集成 FK/IK/Jacobian。
-   将固定参考动作逐步扩展为可配置末端目标或轨迹。
-   比较固定腰部与腰部参与协调的效果。
-   评估不同身体高度和操作目标对可达性、姿态的影响。

验收：有自己实现或集成的控制模块，以及清晰对照实验。

### 阶段四：稳定性与接触鲁棒性（约第 8--10 周）

-   扩展负载、操作高度、接触条件或扰动测试。
-   研究稳定性相关奖励、约束或控制反馈。
-   选择适合平台的方法并与基线比较。
-   主线顺利时，再加入基础阻抗/导纳或接触反馈控制。

验收：有可重复的稳定性和任务性能评估。

### 阶段五：Demo 整合与交付（约第 11--12 周）

-   将移动/接近、身体姿态调整、上肢操作和撤离串成尽可能完整的任务。
-   整理训练配置、实验结果、失败案例和运行说明。
-   形成演示视频、技术文档和简历描述。

验收：项目可运行、可解释、可复现；简历只写实际完成并验证的内容。

## 8. 资源限制、风险与止损原则

-   最大算力预算：单张 RTX
    4090；优先预训练模型和小规模并行环境，按显存实测调整。
-   不假设 SONIC 等大规模通用全身策略能在单卡上完成完整训练。
-   无稳定人形真机资源；项目以仿真研究和评估为主，不承诺真机部署或
    Sim2Real。
-   AGILE 软件依赖和版本可能变化；实施前重新核对仓库版本、Isaac Lab /
    Isaac Sim / Python / CUDA 兼容关系。
-   先验证官方任务，再决定是否大规模改代码。
-   若上肢训练成本过高，优先保证官方 PickPlace
    基线、任务空间控制和稳定性评估。
-   若连续移动操作难以稳定，允许先完成固定工位下的姿态调整与操作。
-   不以论文创新为目标，不为复杂度加入非必要模块。

## 9. 尚待实施阶段决策的问题

1.  AGILE 哪个版本适合当前 AutoDL 镜像与单张 4090；是否固定 v1.3.2。
2.  PickPlace
    能否在单卡可接受时间内训练，合适的并行环境数量和配置是什么。
3.  先以官方右臂/手部任务为主，还是后续扩展双臂；双臂不是预设必做项。
4.  稳定性优先通过奖励、动作约束、任务空间控制、阻抗/导纳还是其他方式改善。
5.  连续移动工位任务是否值得三个月内实现，还是先做好固定工位的全身稳定操作。
6.  哪些评估指标最能支撑结论且能从仿真可靠获取。
7.  是否增加下肢自训练 PPO；它服务于 RL
    运控能力展示，但不能阻塞项目主线。

## 10. 给后续 AI / 开发者的要求

本文是 **V0 需求说明**，不是不可修改的实施指令。

-   先检查 AGILE
    官方仓库、文档、配置和当前版本，不要仅凭本文概括直接写代码。
-   区分官方已有功能、配置即可使用的功能和真正需要自行开发的功能。
-   训练成本、显存、任务能力和性能结论尽量通过官方资料或实际运行验证。
-   优先级：**平台跑通 → 上肢操作与全身稳定主线 → 任务空间控制 →
    评估实验 → 可选的下肢自训练和接触控制增强**。
-   若发现更成熟、更省时或更符合岗位要求的方案，可以提出调整，不必拘泥于
    AGILE 或本文阶段划分。
-   每阶段给出可验收结果、运行记录和下一阶段建议。
-   不为填满技能清单而加入无关工作；**C++ 不作为本项目的刻意规划重点**。

**最终判断标准：**
三个月结束时，是否形成一个基于成熟公开框架、自己完成关键控制扩展、有量化实验支撑、能够清楚解释技术贡献的人形机器人运控项目。
